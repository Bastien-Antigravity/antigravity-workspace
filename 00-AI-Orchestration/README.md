---# 00‑AI‑Orchestration – Obsidian Helper Layer

## 🛠️ How it Works (5‑Dimensional Hybrid System)

The **00‑AI‑Orchestration** folder is the *entry point* that makes the whole vault Obsidian‑aware and enforces the **5‑Dimensional Hybrid System** for every markdown document, tag, and visual artefact.

| Dimension | What it means for the vault | Implementation (files / scripts) |
|-----------|-----------------------------|-----------------------------------|
| **1️⃣ Shallow Folders (PARA + Diátaxis)** | - *Projects, Areas, Resources, Archives* (PARA)  <br> - *How‑to, Reference, Concept, Explain* (Diátaxis) <br> This separation keeps generic workflows (`07‑Core‑KMS`) apart from domain‑specific rules (`03‑Tech‑Stack`). | Folder layout under the repo root; `scripts/ensure_frontmatter.py` uses the layout to place new notes.
| **2️⃣ Strategic MOCs** | Navigation starts at a **Map of Content** – e.g. `[[Ecosystem‑Map‑MOC]]`.  MOCs act as high‑level tables of contents for each major area. | `Ecosystem-Map-MOC.md` (generated by the **Squad‑Orchestrator** role) and the `Role‑Prompts/5D‑Hybrid‑System.md` role that auto‑creates new MOCs.
| **3️⃣ Live Dashboards** | Dataview queries that dynamically track **Tasks**, **Bugs**, and **Fleet‑Health** across the entire vault. | `dashboards/Tasks.md`, `dashboards/Bugs.md`, `dashboards/Fleet-Health.md` – refreshed by `scripts/ensure_frontmatter.py` and `scripts/normalize_tags.py`.
| **4️⃣ Visual Topologies** | Infinite 2‑D boards (Obsidian Canvas) for infrastructure mapping, service topology, and process flows. | Canvas files such as `Infrastructure.canvas`, `Process-Flow.canvas` located next to related MOCs.
| **5️⃣ Bidirectional Links** | Zettelkasten‑style graph of architectural decisions. The **5‑Dimensional Hybrid System** role runs a linker that suggests missing `[[Links]]` and keeps the graph dense. | `Role-Prompts/5D‑Hybrid‑System.md` contains the maintenance logic; the linker is invoked by the **Squad‑Orchestrator** during each session.

---

### Core Responsibilities of this Layer

1. **Tag taxonomy** – a single source of truth (`tags.yaml`) that all agents read and validate.
2. **YAML front‑matter injection** – every `.md` gets the required metadata (title, created/updated timestamps, tags) via `scripts/ensure_frontmatter.py`.
3. **Folder enforcement** – new notes are automatically placed in the correct PARA/Diátaxis location.
4. **MOC creation** – the **Squad‑Orchestrator** creates or updates the ecosystem MOC at the start of each session.
5. **Live‑Dashboard refresh** – Dataview‑based dashboards stay up‑to‑date without manual effort.
6. **Graph upkeep** – the **5‑D Hybrid System** role periodically runs a link‑suggestion routine to keep the Zettelkasten graph healthy.

---

### How Agents Use This Layer

- **Squad‑Orchestrator** (role in `00‑AI‑Orchestration/Role-Prompts/`) loads the tag taxonomy, runs the front‑matter injector on the whole vault, and publishes the ecosystem MOC.
- **5‑D Hybrid System** (role) is the self‑healing maintainer that enforces all five dimensions on existing and newly created notes.
- **Persona‑Extractor** (role) reads the documentation generated here to feed the RAG engine.

---

### Quick Start for Contributors

1. **Create a new note** – the orchestrator will automatically:
   - Place it in the correct PARA folder.
   - Add the right tags from `tags.yaml`.
   - Insert a YAML front‑matter block.
   - Link it into the appropriate MOC.
2. **Run the maintainer** – `python3 scripts/ensure_frontmatter.py` can be run manually to re‑apply the rules.
3. **Add a tag** – edit `tags.yaml` and run `python3 scripts/normalize_tags.py`.
